# Контракт бизнес-события для выгрузки из 1С

Обычный журнал регистрации полезен для технической диагностики, но часто не
содержит бизнес-корреляцию и смысл перехода. Для анализа процесса нужен
отдельный append-only export с такими полями:

| Поле | Назначение |
| --- | --- |
| `event_id` | Стабильный UUID исходного бизнес-события. |
| `occurred_at` | Время события в ISO 8601 с timezone. |
| `case_id` | Явная корреляция процесса, например заявка или заказ. |
| `activity` | Бизнес-действие, а не имя процедуры BSL. |
| `document_ref` | Обезличенная ссылка на документ и его тип. |
| `state_before` / `state_after` | Состояния для анализа возвратов и отклонений. |
| `actor_role` | Роль вместо ФИО, если для анализа достаточно роли. |
| `source_system` | Контур 1С или внешний сервис. |
| `correlation_id` | Техническая связь с HTTP, очередью или интеграцией. |
| `reason_code` | Код причины для корректировок и ручных решений. |

До экспорта нужно исключить ФИО, реквизиты, свободный текст с персональными
данными и значения, не нужные для аналитики. Удаление этих полей должно
происходить до передачи файла в исследовательское хранилище.
